# CLAUDE.md – Filecon monorepo

File-type icons (703 formats, 3 styles) for JS, Web Components, React, Preact, React Native, Vue, Svelte, Solid,
Angular, Astro, Electron, Tauri, Iconify, CSS, Rust (+ Dioxus), VS Code and Python. Website https://filecon.dev, npm scope `@filecon`, license Apache-2.0.

## Hard rules

- `icon-pack/` is the **read-only source of truth**. Never change its SVGs, `manifest.json`, `resolve_icon.py` or
  `generate_file_icons.py`. Problems with icons go into `ISSUES.md` – do not fix them.
- **Publish only when the user explicitly asks for it** (npm, crates.io, …), following `docs/publishing.md`.
  Otherwise check packages only with `pnpm pack:check`, `pnpm pack`, `npm publish --dry-run` or
  `cargo publish --dry-run`.
- Never commit generated code: `src/generated/`, `packages/*/LICENSE|NOTICE`, crate assets (see `.gitignore`).
- Code, docs and commit messages in English, Conventional Commits (`feat(react): …`, `fix(shared): …`).
- Commits are authored by `rafaelk-f` only; no `Co-Authored-By` or similar trailers. Owner/author in package
  metadata is `dutobo`, `rafaelk-f` is a contributor.
- `.env` holds registry tokens (`key: value` lines) – never print or commit them; use them only for a publish
  the user asked for, passed as environment variables or a temporary npmrc that is deleted afterwards.

## Layout

| Path | |
|---|---|
| `icon-pack/` | source of truth (SVGs, manifest, reference resolver, test cases) |
| `tools/codegen/` | TypeScript codegen: pack + templates → packages (`pnpm codegen`) |
| `tools/templates/<fw>/` | one template per framework: `template.ts` (package.json parts + generated files) and `files/` (scaffolded sources; `*.tpl` are rendered with `{{var}}`, `{{#flag}}…{{/flag}}`) |
| `tools/testkit/` | shared conformance tests (rendered SVG vs. pack SVG, a11y, resolver cases) |
| `packages/shared` | hand-written core: types, resolver, render helpers, SVG assets |
| `packages/<fw>`, `packages/<fw>-{default,gray,solid}` | generated from `tools/templates/<fw>` – **edit the template, not the copy** |
| `packages/electron`, `packages/tauri` | hand-written Electron helpers / Tauri JS binding |
| `packages/iconify`, `packages/css` | asset packages; data written by `tools/codegen/src/assets.ts`, wrapped by `scripts/build.mjs` |
| `crates/filecon` | Rust crate; `icons/`, `src/generated.rs`, LICENSE/NOTICE and test data are generated by the codegen |
| `crates/filecon-dioxus`, `crates/tauri-plugin-filecon` | Dioxus component and Tauri 2 plugin on top of `filecon` |
| `extensions/vscode` | VS Code file icon theme; icons/themes generated by `tools/codegen/src/vscode.ts` |
| `ports/python` | Python package; icons/resolver copy generated by `tools/codegen/src/python.ts` |
| `docs/` | additional documentation (`sizes.md`, …) |

## Commands

```sh
pnpm install
pnpm codegen       # idempotent: scaffold packages from templates + write src/generated/**
pnpm lint          # biome check .
pnpm typecheck     # codegen + tsc/svelte-check per package (dev sources via "@filecon/source" condition)
pnpm build         # codegen + build all packages (topological)
pnpm test          # vitest in every package + tarball check + tree-shaking check + cargo test
pnpm lint:rust     # cargo fmt --check + clippy -D warnings
pnpm pack:check    # pnpm pack every package, verify LICENSE/NOTICE/README/dist and no sources/tests
pnpm sizes         # size report -> docs/sizes.md (--check: fail if one icon import > 16 kB)
```

Order for a full check: `pnpm lint && pnpm typecheck && pnpm build && pnpm test`.

## How the packages fit together

- `@filecon/shared`: `IconName`, `Style`, `Theme`, `resolveIcon`, render helpers, SVGs in `dist/svg`.
- `@filecon/js[-style]`: owns the icon data (`/data` entry). Every framework package `@filecon/<fw>[-style]`
  imports its data from the matching js package – icon data exists once per style variant.
- Data = inner SVG markup only (no outer `<svg>`, no `<title>`). `default`/`gray` are stored "themed": light colors
  plus `fc-t*` classes; `shared` derives light, dark and `auto` (embedded `prefers-color-scheme` stylesheet) from it.
  The class table is derived from the pack's light/dark pairs by the codegen, which verifies the round trip.
- Single-style packages have the same API without the `style` option/prop.

## Adding a framework

1. Create `tools/templates/<fw>/template.ts` (`defineTemplate`) and `tools/templates/<fw>/files/`.
2. Use `src/generated/variant.ts` (always generated: `FIXED_STYLE`, `STYLES`, `StyleOption`, `iconData`).
3. Add a test that calls `conformanceSuite` from `@filecon/testkit`.
4. `pnpm codegen && pnpm install && pnpm build && pnpm test`. The codegen creates all four packages.

## Conventions

- TypeScript strict, ESM first (`"type": "module"`), tsup for ESM + CJS + `.d.ts` where possible.
- Every published package: `LICENSE` + `NOTICE` (copied from the pack by the codegen), `"sideEffects": false`,
  `publishConfig: { access: "public", provenance: true }`, version managed by Changesets (fixed group).
- Workspace packages resolve each other's sources during typecheck through the custom export condition
  `@filecon/source`; it is stripped from the published `exports` (`publishConfig.exports`).
- The repository must live on a file system with symlink support (not exFAT).
- Module-level component definitions that reference the icon map (`FileIcon`) must be `/*#__PURE__*/` and must not
  contain spreads in the call arguments, otherwise a single-icon import pulls in all icons (`pnpm sizes --check`).
- When writing files from Python on Windows use `newline=""` (LF only).
