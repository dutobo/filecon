# tauri-plugin-filecon

[Tauri 2](https://v2.tauri.app) plugin for the [Filecon](https://filecon.dev) file-type icons: **703 formats** in
nine styles, picked by file name, extension or magic bytes. The SVGs are embedded in the binary through the
[`filecon`](https://crates.io/crates/filecon) crate.

Pure Rust, no native code: works on Windows, macOS, Linux, iOS and Android.

![The same file icons in all nine Filecon styles, light and dark](https://raw.githubusercontent.com/dutobo/filecon/main/docs/previews/styles.png)

More previews (a grid and a category overview per style): [docs/previews](https://github.com/dutobo/filecon/tree/main/docs/previews#readme).

## Install

```sh
# in src-tauri/
cargo add tauri-plugin-filecon
# JavaScript binding
npm install @filecon/tauri
```

```toml
# src-tauri/Cargo.toml
[dependencies]
tauri-plugin-filecon = "0.3"
# only one style (smaller binary):
# tauri-plugin-filecon = { version = "0.3", default-features = false, features = ["style-solid"] }
```

Register the plugin:

```rust
// src-tauri/src/lib.rs
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_filecon::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

Allow the commands in a capability:

```json
// src-tauri/capabilities/default.json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "filecon:default",
    "filecon:allow-icon-for-path"
  ]
}
```

`filecon:allow-icon-for-path` is optional; add it only if the frontend may let the plugin read files.

## Permissions

| Identifier | |
|---|---|
| `filecon:default` | `allow-resolve` + `allow-icon` (no file system access) |
| `filecon:allow-resolve` / `filecon:deny-resolve` | `resolve` |
| `filecon:allow-icon` / `filecon:deny-icon` | `icon` |
| `filecon:allow-icon-for-path` / `filecon:deny-icon-for-path` | `icon_for_path` (reads the first 1 KB of a file) – **not** in `default` |

See [`permissions/autogenerated/reference.md`](permissions/autogenerated/reference.md).

## JavaScript

The binding is the npm package `@filecon/tauri`. The raw commands are:

| Command | Arguments | Returns |
|---|---|---|
| `plugin:filecon\|resolve` | `{ fileName: string }` | `string` – icon name, `"empty"` if nothing matches |
| `plugin:filecon\|icon` | `{ name: string, style?: Style, theme?: Theme }` | `string` – SVG document; unknown names give the `empty` icon |
| `plugin:filecon\|icon_for_path` | `{ path: string, style?: Style, theme?: Theme }` | `{ name: string, svg: string }` |

```ts
type Style = "default" | "gray" | "solid"; // default: "default"
type Theme = "light" | "dark";             // default: "light"; ignored by "solid"
```

```ts
import { invoke } from "@tauri-apps/api/core";

const name = await invoke<string>("plugin:filecon|resolve", { fileName: "report.pdf" }); // "pdf"
const svg = await invoke<string>("plugin:filecon|icon", { name, style: "solid" });
const { name: detected, svg: icon } = await invoke<{ name: string; svg: string }>(
  "plugin:filecon|icon_for_path",
  { path: "/home/me/app.db", theme: "dark" }, // "db-sqlite" for SQLite files
);
```

`name` in `icon` also accepts extensions (`".PDF"` → `pdf`). The SVGs are the unmodified pack files
(40×40, `viewBox="0 0 40 40"`, with a `<title>` containing the icon name).

### `icon_for_path`

Resolution order: file name → magic bytes (at most the first 1024 bytes are read) → extension → `"empty"`.
If the file cannot be read (missing, no permission, a directory) the command falls back to the name and extension;
it never returns an error. The file is read on Tauri's async runtime, not on the main thread.

On **Android and iOS** the command needs a real file system path (for example inside the app's data directory).
`content://` URIs from the Android document picker and security-scoped iOS URLs cannot be opened as paths and fall
back to name-only resolution (the extension in the URI, if any).

## Rust API

The command logic is also available as plain functions in `tauri_plugin_filecon::icons`:
`resolve(file_name)`, `icon(name, style, theme)`, `resolve_path(path)`, `icon_for_path(path, style, theme)`,
`read_head(path)` and `to_icon_name(name)`, with the serde types `Style`, `Theme` and `IconForPath`.

## Features

| Feature | Default | Embeds |
|---|---|---|
| `style-default` | yes | `default/light`, `default/dark` |
| `style-gray` | yes | `gray/light`, `gray/dark` |
| `style-solid` | yes | `solid` |
| `style-papered` | yes | `papered/light`, `papered/dark` |
| `style-papered-flat` | yes | `papered-flat/light`, `papered-flat/dark` |
| `style-papered-craft` | yes | `papered-craft/light`, `papered-craft/dark` |
| `style-scratch` | yes | `scratch/light`, `scratch/dark` |
| `style-chalk` | yes | `chalk/light`, `chalk/dark` |
| `style-iconic` | yes | `iconic/light`, `iconic/dark` |

If a requested style is disabled, the first enabled style is returned instead.
